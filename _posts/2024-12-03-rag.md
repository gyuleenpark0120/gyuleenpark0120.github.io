<div class="paper-what">
  <div class="paper-section-label">What this paper does</div>

Once an LLM finishes training, its knowledge is frozen at that point. It has no access to information that emerged afterward, and tends to confidently fabricate details not in its training data — hallucination.

The solution this paper proposes is simple but powerful: instead of asking the model to answer directly, first retrieve relevant documents from an external source, then have the model read them and generate an answer. Like an open-book exam. A retrieval engine combined with a language model.

The key advantage: you only need to update the knowledge database — no retraining the model — to reflect new information. Tested on Wikipedia, it achieved state-of-the-art on multiple open-domain QA tasks at the time.

</div>

<div class="paper-takeaway">
  <div class="paper-section-label">Takeaway</div>
  <div class="takeaway-item">
    <span class="ti-marker">◆</span>
    <span>The core design principle — separating parametric (in-model) knowledge from non-parametric (retrieved) knowledge — became the foundation for all subsequent RAG research. The model doesn't need to memorize everything; it needs to learn how to search well and how to read well.</span>
  </div>
  <div class="takeaway-item">
    <span class="ti-marker">◇</span>
    <span>Building a battery literature pipeline firsthand made this concrete: the bottleneck in RAG is almost always retrieval quality, not generation. Chunking strategy, embedding model choice, re-ranking — if retrieval fails, it doesn't matter how good the generator is.</span>
  </div>
</div>
