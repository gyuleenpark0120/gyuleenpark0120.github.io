<div class="paper-what">
  <div class="paper-section-label">What this paper does</div>

When you give an LLM a complex question, there were two approaches: "just think" (chain-of-thought: reason step by step) or "just act" (call tools directly). This paper proposes alternating between the two.

The pattern is simple: **Think → Act → Observe**, repeated. "To answer this I need to look up a paper" (think) → run a search (act) → check the results (observe) → "Is this enough, or do I need another search?" (think) → ... Since the model can adjust its next action based on what the tool returns, it can handle far more complex tasks than either approach alone.

</div>

<div class="paper-takeaway">
  <div class="paper-section-label">Takeaway</div>
  <div class="takeaway-item">
    <span class="ti-marker">◆</span>
    <span>ReAct's real contribution isn't "use tools" — it's "integrate reasoning traces with tool calls." Making the model articulate why it's using a tool before using it creates an audit trail that reduces errors mid-task. LangChain, LlamaIndex, and virtually every production agent framework today is built on this pattern.</span>
  </div>
  <div class="takeaway-item">
    <span class="ti-marker">◇</span>
    <span>The critical mechanism is that observations feed back as context for the next thought. Without this, it's just an LLM that uses tools. With it, it becomes an adaptive agent that revises its strategy based on what tools actually return. This feedback structure was foundational when designing the multi-agent loop in my Deepspace project.</span>
  </div>
</div>
